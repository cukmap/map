# 지도 데이터의 틀

이 문서는 cukmap 지도 데이터가 어디에 어떤 모양으로 들어 있는지, 그리고 새 자료(예: 학교에서 받은 도면)가 들어왔을 때 무엇을 바꾸면 되는지를 정한다. 규칙을 바꿀 때는 이 문서부터 고친다.

## 1. 폴더 구조

학교 전체(성심교정, 성의교정, 성신교정)를 담을 수 있게 교정마다 폴더를 나눈다. 지금은 성심교정(`songsim`)만 있다.

```
data/campuses/
  songsim/                성심교정
    buildings/
      order.json          건물 그리는 순서
      <건물ID>/
        building.json     외곽·높이·층수·외관 설정(창 모양, 색 등)
        roof.json         옥상 요소(태양광, 옥탑, 설비) — 있는 건물만
        details.js        사진을 보고 손으로 만든 장식(덧붙이는 층)
        indoor/           실내 도면 — 공개 보류, 저장소에 올리지 않음
          indoor.json     층 목록, 층 사이 연결
          <층>.json       벽·창·문·방 이름·보행망
          <층>.plan.jpg   도면 선 그림
          <층>.rooms.png  방 영역 지도(평면 지도용)
    places/<장소ID>/details.js  건물이 아닌 장소(언덕, 계단, 운동장)의 장식
    campus/               지형, 등고선, 경계, 도로, 장소 이름, 나무, 소품, 연석·옹벽
    network/              보행망: nodes.json(교차점·출입구·교문), edges.json(길)
    images/               바닥 재질 지도, 지면·항공 사진 텍스처
    details-order.json    장식 파일을 붙이는 순서
    legacy/               예전 모델(쓰지 않게 되면 지운다)
  songeui/                성의교정(나중에)
  songsin/                성신교정(나중에)
src/                      지도를 그리는 코드(역할별 파일, 이름 순서대로 붙음)
site/index.html           화면 뼈대(메뉴·버튼·글자)
tools/build.py            위 모든 것을 dist/index.html 한 파일로 묶음
```

**지도 모양은 여러 개, 데이터는 하나.** 3D 지도, 지상 시점, 2D 평면 지도는 모두 같은 데이터를 읽는다. 데이터를 고치면 모든 지도 모양에 함께 반영된다. 지도 모양별로 데이터를 복사하지 않는다.

**이름 표기.** 교정 이름은 학교 표기를 따라 붙여 쓴다(성심교정, 성의교정, 성신교정).

## 2. 바뀌지 않는 기준

**좌표.** 모든 위치는 미터 단위 평면 좌표 `(x, z)`로 적는다. x는 동쪽, z는 남쪽이 +이다. 원점은 교정마다 따로 두고 `campus/meta.json`의 `origin`에 적는다. 성심교정의 원점은 위도 37.4867837, 경도 126.8013923이다.
성심교정에서 위경도로 바꿀 때는 다음 식을 쓴다.

```
위도 = 37.4867837 − z / 110950
경도 = 126.8013923 + x / 88270
```

새 자료가 다른 좌표계(도면 좌표, EPSG:5186 등)로 오면, 변환해서 이 좌표로 넣는다. 원래 좌표계로 저장하지 않는다.

**높이.** `y`는 해발 고도(m)이다. 지형(`campus/terrain.json`)도 같은 기준이다.
아직 일부 건물의 층 높이는 "1층 바닥 + 층고 × 층" 계산으로 코드(`src/21-floor-levels.js`)에 들어 있다. 다음 단계에서 층마다 해발 고도를 데이터에 적는 방식으로 옮긴다. 니콜스관 4층 = 마리아관 4층 = 비르투스관 3층 = 밤비노관 3층처럼, 사용자가 확인한 같은 높이 연결은 이 값으로 지킨다.

**ID.** 한 번 정한 ID는 바꾸지 않는다. 제보, 길찾기, 게임, 다른 팀의 프로젝트는 좌표가 아니라 ID로 장소를 가리킨다. ID는 교정 안에서만 겹치지 않으면 되고, 교정 밖에서 가리킬 때는 앞에 교정 ID를 붙인다(예: `songsim/nichols`, `songsim/nichols/3F/N301`).

| 대상 | ID 모양 | 예 |
|---|---|---|
| 교정 | 영문 소문자 | `songsim`, `songeui`, `songsin` |
| 건물 폴더 | 영문 소문자 | `nichols`, `dasol`, `kimsuhwan` |
| 건물 코드(화면 표시) | `building.json`의 `code` | `N`, `D`, `K` |
| 층 | `B1`, `1F` … `RF` | `3F` |
| 방 | 도면의 호실 번호 | `N301` |
| 출입구·교차점 | `network/nodes.json`의 `id` | `E_N_E1`, `P_GATE_MAIN` |
| 장소 | 영문 소문자 | `wailing-hill`, `stadium` |

## 3. 출처와 확인 정도

모든 값은 어디서 왔는지 남긴다. 지금 `building.json`에는 `source`, `heightStatus`, `floorSource`, `ledger` 같은 항목이 건물마다 조금씩 다른 이름으로 들어 있다. 앞으로 새로 넣거나 고치는 값은 아래 모양으로 통일한다.

```json
"_src": {
  "floors": { "from": "건축물대장", "date": "2022-12-05", "level": "문서" },
  "outline": { "from": "NGII 2025 수치지도", "level": "측량" },
  "entrance_E2": { "from": "현장 사진 2026-11-10", "level": "추정" }
}
```

`level`은 다음 넷 중 하나로 적는다.

- **측량**: 측량 자료(수치지도, CAD)
- **문서**: 공문서, 대장, 도면
- **확인**: 현장 사진이나 사용자가 직접 확인
- **추정**: 영상·사진 판독, 계산

더 높은 단계의 자료가 들어오면 낮은 단계 값부터 바꾼다. 지도 화면의 "추정" 표시는 이 값으로 정한다.

## 4. 새 도면이 들어왔을 때

1. 도면을 변환 도구로 `indoor/` 형식(층별 벽·창·문·방 이름)으로 바꾼다. 변환 도구는 `tools/`에 둔다(입찰공고 도면 변환에 쓴 과정을 옮겨 올 예정).
2. 해당 건물의 `indoor/` 폴더만 새 파일로 바꾼다.
3. 외곽이 달라졌으면 `building.json`의 `poly`와 `spec.parts`를 고치고 `_src`를 `문서`로 올린다.
4. `details.js`의 장식이 새 외곽과 어긋나는지 보고 위치를 맞춘다. 장식은 외곽 모서리나 출입구 ID를 기준으로 놓기 때문에 대부분 그대로 맞는다.
5. 다른 건물, `src/`, 보행망은 건드리지 않는다. 출입구 위치가 달라졌을 때만 `network/nodes.json`에서 그 출입구 좌표를 고친다.

## 5. 덧붙이는 층(details.js)

`details.js`는 기본 모양(외곽을 층수만큼 세운 건물) 위에 사진을 보고 얹은 장식이다. 캐노피, 계단, 간판, 교표, 난간 같은 것들이다.

- 한 파일은 한 건물(또는 장소)만 다룬다.
- 파일 안 단락마다 근거와 날짜를 첫 줄 주석으로 적는다(예: `// 3b) 다솔관 (2026-11-12 사용자 현장 사진 16장): …`).
- 기본 모양을 바꾸는 일(층수, 외곽, 색)은 여기서 하지 않고 `building.json`에서 한다.

## 6. 아직 코드에 남아 있는 데이터

처음 분해(2026-11-16)는 화면이 바뀌지 않는 것을 우선으로 했다. 그래서 아래 항목은 아직 `src/` 코드 안에 값으로 들어 있고, 차례로 데이터 파일로 옮긴다.

| 파일 | 들어 있는 값 | 옮길 곳 |
|---|---|---|
| `src/10-terrain-edits.js` | 안드레아 마루광장·콘서트홀 앞·김수환관 광장 지형 평탄화 | `campus/terrain-edits.json` |
| `src/21-floor-levels.js` | 건물별 1층 바닥 높이·층고 | 각 `building.json`의 층별 해발 고도 |
| `src/22-*.js`, `src/23-*.js` | 현장·공식 사진으로 정한 벽 색·창 모양·지붕 | 각 `building.json`의 `spec` |
| `src/24-library-roof.js`, `25-kimsuhwan-stairs.js`, `26-michael.js` | 건물 하나에만 해당하는 형상 | 각 건물의 `details.js` |

## 7. 빌드

```
python3 tools/build.py            # dist/index.html (실내 포함, 실내 자료가 있는 컴퓨터에서만)
python3 tools/build.py --public   # 공개용(실내 도면·학교 사진 제외)
```
